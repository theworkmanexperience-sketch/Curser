**The model is right and the runtime cannot represent it.** A Gate-A run today has exactly two available outcomes, and neither is Gate A:

```
declare  regeneration_scope.mode = CANONICAL_EDITORIAL_TIMELINE
  → G-12 passes, the run proceeds, and the output is INDISTINGUISHABLE
    from a governed production artifact

declare anything else, or omit it
  → G-12 fails the run before the first write. Gate A produces nothing
```

**There is no third state. Gate A is currently unrepresentable, not merely unimplemented.**

# 1 · WHY THE MODEL IS ARCHITECTURALLY CORRECT

**It is the platform's own doctrine applied to execution.** `ER-003` establishes that custody is not authority and that custody is immutable. Gate A / Gate B is that distinction moved from artifacts to runs:

| | act | custody | authority |
|---|---|---|---|
| **Gate A** | running a parser, extractor, validator or generator | `MACHINE` | **NONE** |
| **Gate B** | making an output a governed artifact | `EXECUTIVE` | **DECIDES** |

**This resolves the ED-006 contradiction rather than adjudicating it.** The Order in force releases the lock on two conditions; the readiness program named eight. **Those were never the same question** — one asks whether the generator may run, the other whether its output may become canonical. Separating them makes both true.

**And the platform already behaves this way elsewhere.** The `APPROVED_VIEWING_MASTER` register is precisely a Gate B: renders exist freely; exactly one may be `APPROVED`; *"A render absent from this register is NOT approved. Silence is not approval."* **The pattern being proposed for execution is already governing renders.**

# 2 · WHERE THE DISTINCTION BREAKS — THREE PLACES

## 2.1 · Break 1 — no machine-readable status on any artifact

Every generated artifact opens with this header. Measured from `CONDUCTOR_SCORE.yaml` and `VISUAL_EVENT_REGISTRY.yaml`:

```
# RUN_ID: WECAPE-AR2-SPRINT3A-20260822-114028
# Sprint: G3-ESS-001 Rev A (Sprint 3A) - governed production run
# Generated by: intelligence/p2/ess/scripts (see EXECUTION_LOG.md)
# Authoritative inputs (SHA-256):
#   Filmage_Editor.mp4                      a53655fc…
#   Alpha RoudUp Part 2.fcpxmld/Info.fcpxml 2bf06853…
#   Alpha RoudUp Part 2_SRT__SRT 2_...srt   89d61f96…
#   P2_LOCK_timing.json                     e91318a6…
# Editorial lock: 4846.625 s
# Repository commit at launch: ff0c45f7…
artifact_id: CONDUCTOR_SCORE
engine: MIE
version: 1.1.0
```

**The only claim of status in the entire artifact is the phrase `governed production run` — inside a comment, in free text, written into the generator's template.** `[E]`

**A Gate-A run would reproduce that phrase verbatim**, because it is template text rather than a computed field. The artifact would assert its own governance while having none.

**There is no `status`, no `authority`, no `custody` field.** `artifact_id: CONDUCTOR_SCORE` is a name. `engine: MIE` is a component. `version: 1.1.0` is a revision. **None of them expresses class.**

**What the runtime *can* already distinguish:** `RUN_ID`, `regen_run_id`, `git_commit`, and the four input hashes. **Two runs are always tellable apart.** The gap is precise and worth stating exactly:

> **The runtime can distinguish one run from another. It cannot distinguish an authorized run from an unauthorized one.**

Instance is captured. **Class is not.**

## 2.2 · Break 2 — the output path is caller-supplied

`gen_artifacts_v2.py` line 31:

```python
OUT = _A.out
```

**The output directory is a command-line argument.** This is correct parameterization — it is the `B-4` work and it is what makes the generator production-agnostic. **It also means nothing prevents a Gate-A run from writing into `intelligence/p2/ess/`.**

There is no default-deny, no allow-list, no guard that asserts the destination, and no convention recorded anywhere that experimental output belongs elsewhere.

**This repository has already been damaged twice by exactly this shape.** `APPROVED_VIEWING_MASTER` documents one in its own words:

> *"the filename is **IDENTICAL** to the Approved Viewing Master's `Alpha RoudUp Part 2.m4v`. **Not similar: identical.** The two are distinguishable only by directory, size, runtime and hash."*

And `DAY2_PARENT_FORENSIC_AUDIT` documents the second — a duplicate `Day 2 Part 3` directory holding a different asset set, cleared only by hashing.

**A Gate-A output written beside a governed artifact, under the same filename, carrying the same header template, would be the third — and the worst, because the two would be byte-similar rather than merely name-similar.**

## 2.3 · Break 3 — `G-12` admits exactly one mode

```python
scope = ctx.get('regeneration_scope') or {}
mode  = scope.get('mode')
if mode != 'CANONICAL_EDITORIAL_TIMELINE':
    _fail('G-12', 'context declares regeneration_scope.mode=%r; ERO-001 §2 requires '
                  'CANONICAL_EDITORIAL_TIMELINE. A run whose scope is undeclared or '
                  'different is not the run the Order authorises.')
```

**The guard is correct and it is doing exactly what ERO-001 §2 told it to do.** It is not a defect.

**But it is a binary where Gate A needs a third value.** `CANONICAL_EDITORIAL_TIMELINE` passes; everything else, including an honest `EXPERIMENTAL`, stops the run before the first write.

**So the guard that most reliably protects canonical output is also the reason Gate A cannot exist.** That is the finding, and it is not a criticism of the guard — it is a consequence of the guard having been written when only one kind of run was contemplated.

# 3 · COULD AN EXPERIMENTAL ARTIFACT PRESENTLY BECOME INDISTINGUISHABLE?

**Yes — and the worst case is not the obvious one.**

| scenario | distinguishable? | by what |
|---|---|---|
| Gate A run, **different inputs**, written elsewhere | **YES** | different input hashes in the header; different path |
| Gate A run, **different inputs**, written into the governed tree | **YES, on inspection** | input hashes differ — **but the filename and template are identical, so nothing signals that inspection is needed** |
| **Gate A run, same inputs, same generator, written into the governed tree** | **NO, in any practical sense** | **Only `RUN_ID` and `git_commit` differ. Same filename, same `artifact_id`, same four input hashes, same `governed production run` string, same editorial lock, same schema** |

**The third row is the likely case, not the exotic one.** The natural reason to run a generator under Gate A is to test it against known inputs — which means the same inputs, and therefore the maximum resemblance.

**Two artifacts differing only in a run identifier, one governed and one not, with nothing in either declaring which is which.**

# 4 · GATE B — SHOULD PROMOTION BE THE ONLY MECHANISM?

**The Order asks whether Executive promotion should become the sole mechanism for five acts. Evidence supports all five, and the repository already enforces one of them.**

| act | evidence |
|---|---|
| **establish canonical lineage** | `lineage_status: PRODUCTION` and `SUPERSEDED_ASSEMBLY` were set by Executive Order, never computed. `INGEST-0824` sits at `PREPARED_NOT_EXECUTED` awaiting exactly this |
| **bind governed hashes** | The four-source chain is closed by hash in artifact headers. **Binding a hash is asserting an artifact's identity** — and `CF-001` is what happens when that assertion is made informally |
| **update registries** | Already enforced. `APPROVED_VIEWING_MASTER` records that its 2026-08-26 quarantine required *"a SINGLE exception to the standing suspension on registry modification"* — by Order, for one entry |
| **replace governed artifacts** | `DOC-002` — regenerate, never patch. Replacement is regeneration, and regeneration is under `RUN_ID` lock |
| **authorize publication** | `SOP-06` gates. Gate 1 currently holds 73 contributed files out of the edit |

**Four of the five are already Executive in practice. Gate B would name a rule the platform is largely following, and close the one gap — hash binding — through which `CF-001` entered.**

# 5 · MINIMUM CHANGES FOR A FUTURE IMPLEMENTATION

**Described, not implemented, and deliberately minimal.** Each maps to one break in §2. **None is authorized here.**

## `M-1` · A status field, computed rather than written

The context declares a class; the generator propagates it into every artifact as a **machine-readable field**, not a comment. Consistent with the platform's rule that the aggregate is computed, never authored.

```
STATUS     EXPERIMENTAL | CANONICAL
AUTHORITY  NONE | <the instrument that promoted it>
CUSTODY    MACHINE
```

**The `Sprint: … governed production run` comment should stop being the status.** It is template text that would follow an experimental run into the world.

## `M-2` · A third regeneration mode, coupled to the destination

`G-12` gains one admissible value. **The mode and the output namespace must be bound to each other**, so an experimental run cannot be written to a canonical path and a canonical run cannot be written outside one. **Two independent flags reproduce the problem; one coupled decision does not.**

```
mode = CANONICAL_EDITORIAL_TIMELINE   →  governed namespace   →  STATUS CANONICAL
mode = EXPERIMENTAL                   →  experimental namespace only  →  STATUS EXPERIMENTAL
anything else                          →  fail shut, as today
```

## `M-3` · A destination guard

A new guard asserting that the resolved output directory is permitted for the declared mode, **failing shut before the first write** — the posture every existing guard already holds. This is the control that closes §2.2, and it is the one whose absence has already produced two look-alike incidents.

## `M-4` · Promotion as a recorded act

Gate B needs an artifact, not a convention. **The `APPROVED_VIEWING_MASTER` register is the working precedent** — one approved entry, everything else explicitly reference-only, *silence is not approval.* Promotion should leave a record naming what was promoted, from which run, by which instrument.

# 6 · TWO OBSERVATIONS OFFERED WITHOUT RECOMMENDATION

**Gate A widens what the platform can safely do, and that is its real value.** Today the generator is locked because running it and blessing its output are the same act. Under Gate A the ETC extractor could be pointed at the 08-24 lineage, the generator exercised against real inputs, and `ECR-003` run against the citations — **all without any of it becoming governed.** The single largest constraint on this platform is that it cannot rehearse.

**And Gate A is the honest home for work that has already happened.** The ETC extractor was validated by regenerating a governed artifact — a run that produced bytes identical to a canonical file while carrying no authority whatsoever. **That was a Gate A execution in everything but name**, performed under a bespoke Order because no standing category existed for it.
